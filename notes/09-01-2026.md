# Sistemas Expertos

Un **sistema experto** es un programa de IA que emula la capacidad de decisión de un experto humano en un dominio específico.

---

## Arquitectura de un Sistema Experto

Un Sistema Experto está conformado por los siguientes componentes:

### 1. Base de Conocimientos (BC)

Almacena el saber experto del dominio. El conocimiento se representa mediante:

- **Reglas** (si-entonces)
- **Marcos**
- **Lógica formal**
- **Redes semánticas**
- **Ontologías**

### 2. Base de Datos o Base de Hechos

Guarda los datos concretos del problema actual. Son los hechos conocidos en un momento dado.

### 3. Motor de Inferencia

Es el "cerebro" del sistema. Combina la base de conocimientos con la base de hechos para deducir nuevas conclusiones, imitando el razonamiento humano.

### 4. Módulo de Justificación

Permite explicar al usuario **cómo** se llegó a una conclusión, aportando transparencia al proceso de razonamiento.

### 5. Interfaz de Usuario

Facilita la interacción en lenguaje natural, con preguntas bien diseñadas (y opcionalmente gráficos) para obtener información fiable.

---

## Cómo Trabaja el Motor de Inferencia

El motor de inferencia opera mediante **reglas de la forma SI... ENTONCES...**, aplicándolas sobre los hechos para generar nuevas conclusiones. Utiliza dos estrategias principales:

### Encadenamiento Hacia Adelante (*Forward Chaining*)

- **Punto de partida:** hechos conocidos (datos)
- **Dirección:** de abajo hacia arriba (datos → conclusiones)
- **Pregunta que responde:** *"¿Qué puede suceder después?"*
- **Estrategia de búsqueda:** amplitud primero

**Proceso:**
1. Se parte de los hechos disponibles en la base de hechos
2. Se buscan todas las reglas cuya parte SI (condición) se cumple
3. Se disparan esas reglas y se obtienen nuevos hechos
4. Se repite hasta alcanzar el objetivo o no haya más reglas aplicables

**Ejemplo:**

```
Hechos:  {A, B}
Regla 1: SI A y B → C
Regla 2: SI C → E
Regla 3: SI A y E → H

Resultado: Se infiere H (objetivo alcanzado)
```

| Ventajas | Desventajas |
|---|---|
| Funciona bien con datos disponibles | Genera información sin saber si es relevante |
| Puede deducir muchos datos a partir de pocos | El usuario debe ingresar mucha información al inicio |
| Ideal para planificación, monitoreo y control | Puede disparar reglas innecesarias |

### Encadenamiento Hacia Atrás (*Backward Chaining*)

- **Punto de partida:** un objetivo o hipótesis
- **Dirección:** de arriba hacia abajo (conclusión → hechos)
- **Pregunta que responde:** *"¿Por qué sucedió esto?"*
- **Estrategia de búsqueda:** profundidad primero

**Proceso:**
1. Se parte del objetivo que se quiere demostrar
2. Se busca una regla cuya parte ENTONCES (conclusión) coincida con el objetivo
3. Se convierte la parte SI de esa regla en el nuevo subobjetivo
4. Se repite recursivamente hasta encontrar los hechos que lo respaldan

**Ejemplo:**

```
Objetivo: demostrar H
Regla 3: SI A y E → H       → subobjetivo: {A, E}
Regla 2: SI C → E           → subobjetivo: {C}
Regla 1: SI A y B → C       → hechos necesarios: {A, B}

Resultado: A y B están en la base de hechos → H demostrado
```

| Ventajas | Desventajas |
|---|---|
| Búsqueda dirigida, termina al verificar el hecho | El objetivo debe conocerse de antemano |
| Solo considera partes relevantes de la BC | Difícil de implementar |
| Rápido, solo prueba reglas requeridas | Genera un número limitado de conclusiones |

### Comparación Rápida

| Característica | Hacia Adelante | Hacia Atrás |
|---|---|---|
| Técnica | Basada en datos | Impulsada por objetivos |
| Velocidad | Lenta (usa todas las reglas) | Rápida (solo reglas necesarias) |
| Aplicaciones | Monitoreo, planificación, control | Diagnóstico, depuración, clasificación |
| Ejemplo | Predecir reacción del mercado | Diagnosticar una enfermedad |
