# Sistemas Expertos

Sistema de IA que emula la capacidad de decisión de un experto humano en un dominio específico.

---

## Origen

Nacen en **1960-1970** dentro de la IA simbólica, al comprobar que la IA general no era viable y había que enfocarse en **dominios específicos**.

- **1965 — DENDRAL:** primer SE (Stanford) — identifica estructuras químicas
- **1970s — MYCIN:** diagnóstico de infecciones bacterianas (Stanford)
- **1980s — XCON/R1:** configuración de computadoras (DEC); probó el valor comercial

### Fragmentación

```
       Sistemas Expertos
              │
   ┌──────────┼───────────┐
   │          │           │
 Reglas    Casos CBR   Lógica difusa
   │          │           │
 Redes     Aprendizaje   Sistemas
 semánticas/ ML/redes   híbridos
 marcos    neuronales
```

Sucedió porque: los basados en reglas eran difíciles de mantener, el **ML** (años 90-2000) aprendía sin reglas manuales, el **CBR** aportaba experiencia, y la **lógica difusa** manejaba incertidumbre.

## Tipos

| Tipo | Cómo funciona | Ejemplo |
|---|---|---|
| **Reglas** | Reglas SI-ENTONCES encadenadas | MYCIN |
| **Marcos** | Estructuras jerárquicas con atributos y herencia | Clasificar objetos |
| **Lógica** | Deducción formal de predicados | Prolog |
| **Redes semánticas** | Nodos conectados por relaciones | Parentescos |
| **Casos** (CBR) | Recuerda y adapta soluciones previas | Soporte técnico |
| **Difusos** | Lógica difusa para incertidumbre | Climatización |

### Reglas vs Casos

| | Reglas | Casos |
|---|---|---|
| **Conocimiento** | Extraído del experto | Casos reales |
| **Razonamiento** | Deductivo | Recuerdo + adaptación |
| **Aprendizaje** | Actualizar reglas | Añadir casos |
| **Explicación** | Fácil | Difícil |

## Sistemas de Interpretación

Analizan **datos/sensores** y producen una **descripción del estado** que representan. Responden: *"¿qué significa esto?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Datos continuos, ruidosos o incompletos |
| **Salida** | Interpretación o clasificación del estado |
| **Razonamiento** | Encadenamiento hacia adelante, patrones |

**Tipos:** reconocimiento de patrones (voz, imágenes) · interpretación de señales (ECG) · clasificación (mineral, bacteria) · análisis de situaciones (fallas industriales)

**Ejemplos:** DENDRAL (espectrometría → estructura molecular), PUFF (función pulmonar), HEARSAY (voz), analizadores de fallos

```
Entrada → filtrar → comparar con patrones/reglas → correlacionar → interpretación
```

**Ventaja:** procesa grandes volúmenes, consistente, continua y detecta patrones sutiles que un humano no ve.

---

## Sistemas de Predicción

Proyectan la **evolución futura** de una situación a partir del estado actual y de modelos causales. Responden: *"¿qué ocurrirá después?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Estado actual del sistema |
| **Salida** | Consecuencias o comportamientos futuros |
| **Razonamiento** | Simulación de modelos causales |

**Ejemplos:** predicción del clima, efecto de cambios en tasas de interés en el mercado, riesgo de cosechas, propagación de enfermedades.

```
Estado actual → aplicar modelo causal → proyectar consecuencias
```

**Diferencia con interpretación:** la interpretación describe el estado **presente**; la predicción extrapola al **futuro** usando ese estado.

**Ventaja:** anticipa problemas antes de que ocurran (mantenimiento predictivo, prevención).

---

## Sistemas de Diagnóstico

Identifican la **causa o falla** que explica los síntomas observados. Responden: *"¿por qué ocurrió esto?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Síntomas o síntomas anómalos |
| **Salida** | Diagnóstico / causa probable |
| **Razonamiento** | Encadenamiento hacia atrás (guiado por objetivos) |

**Ejemplos:** MYCIN (infecciones bacterianas), CADUCEUS (medicina interna), diagnóstico de fallas en motores o computadoras.

```
Síntomas → hipótesis de causa → verificar (backward chaining) → diagnóstico
```

| Interpretación | Diagnóstico |
|---|---|
| Describe qué hay | Explica por qué ocurrió |

**Ventaja:** localiza la causa exacta en aviones, plantas industriales y medicina, reduciendo el tiempo de reparación.

---

## Sistemas de Diseño

Construyen una **configuración o solución** que cumple con un conjunto de restricciones y requisitos. Responden: *"¿cómo debe estar compuesto?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Requisitos del cliente y restricciones |
| **Salida** | Configuración/plan que satisface los requisitos |
| **Razonamiento** | Búsqueda en espacio de estados + restricciones |

**Ejemplos:** XCON/R1 (configuración de computadoras VAX), diseño de circuitos, planificación de rutas o ensamblajes.

```
Requisitos → elegir componentes → verificar restricciones → configuración final
```

**Diferencia con diagnóstico:** el diagnóstico busca la **causa** de un problema; el diseño **arma una solución** desde cero cumpliendo reglas.

**Ventaja:** genera configuraciones válidas y completas que un humano tardaría mucho en armar, evitando errores (como en XCON).

---

## Sistemas de Planificación

Organizan una **secuencia de acciones** para alcanzar un objetivo, considerando la relación entre acciones (precondiciones y efectos). Responden: *"¿qué pasos seguir para lograrlo?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Estado inicial + objetivo + acciones disponibles |
| **Salida** | Plan: secuencia ordenada de acciones |
| **Razonamiento** | Búsqueda en el espacio de estados + encadenamiento |

**Ejemplos:** planificación de trayectorias de robots, logística/transporte, agendas de tareas, ensamblaje de productos.

```
Estado inicial → elegir acción → verificar precondición → aplicar efectos → ... → objetivo
```

**Diferencia con diseño:** el diseño arma una **configuración** (qué componentes); la planificación ordena **secuencias temporales** (cuándo hacer qué).

**Ventaja:** encuentra una secuencia de pasos válida y ordenada que garantiza llegar al objetivo sin conflictos.

---

## Sistemas de Monitoreo

**Observan continuamente** el comportamiento de un sistema y alertan cuando detectan anomalías o situaciones relevantes. Responden: *"¿está ocurriendo algo anómalo?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Lecturas continuas de sensores en tiempo real |
| **Salida** | Alerta / señal de anomalía o evento esperado |
| **Razonamiento** | Comparación con valores esperados + interpretación |

**Ejemplos:** monitoreo de pacientes en hospitales, vigilancia de plantas nucleares o industriales, control de tráfico, monitoreo de la bolsa.

```
Sensores → comparar con valores esperados → ¿anomalía? → alerta
```

**Diferencia con interpretación:** la interpretación describe el estado puntual; el monitoreo observa **en el tiempo** para detectar desviaciones.

**Ventaja:** detecta problemas en tiempo real, permitiendo actuar antes de que se agraven (prevención).

---

## Sistemas de Instrucción

**Enseñan o entrenan** al usuario, detectando sus errores y guiándolo por un proceso de aprendizaje adaptado. Responden: *"¿cómo puedo enseñar esto?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Acciones/respuestas del estudiante |
| **Salida** | Retroalimentación, corrección o siguiente lección |
| **Razonamiento** | Modelo del alumno + planificación pedagógica |

**Ejemplos:** tutores inteligentes (matemáticas, idiomas), simuladores de entrenamiento (vuelo, medicina), sistemas de práctica guiada.

```
Acción del alumno → evaluar error → diagnosticar causa → dar retroalimentación → siguiente paso
```

**Diferencia con diagnóstico:** el diagnóstico identifica fallas en sistemas; la instrucción usa la detección de errores **para corregir y enseñar**.

**Ventaja:** personaliza la enseñanza según el nivel y errores de cada usuario, mejorando el aprendizaje.

---

## `Sistemas de Control`

**Actúan directamente sobre el entorno** para mantener un sistema dentro de un estado deseado, tomando decisiones automáticas a partir del estado real. Responden: *"¿qué acción debo ejecutar para corregir?"*

| Característica | Detalle |
|---|---|
| **Entrada** | Estado actual del sistema (sensores) |
| **Salida** | Acción de control (actuadores) |
| **Razonamiento** | Interpretación + reglas de acción / corrección |

**Ejemplos:** control de procesos industriales (temperatura, presión), control de vuelo de drones, gestión de inventarios, control de tráfico, climatización inteligente.

```
Sensores → comparar con estado deseado → decidir acción → aplicar → volver a medir
```

**Diferencia con monitoreo:** el monitoreo solo **alerta** las anomalías; el control **corrige** automáticamente.

**Ventaja:** responde en tiempo real sin intervención humana, manteniendo el sistema estable y seguro.

## Sistemas Basados en Reglas

El tipo más clásico. Conocimiento = reglas de producción SI-ENTONCES.

```
IF  fiebre AND tos AND estornudos
THEN  diagnóstico = resfriado común
```

**Componentes:** memoria de trabajo (hechos) · base de reglas · motor de inferencia

| ✅ Ventajas | ❌ Desventajas |
|---|---|
| Modular y fácil de actualizar | Difícil de mantener a cientos de reglas |
| Explicable paso a paso | Explosión combinacional |
| No se reescribe el motor | Solo conocimiento explícito |
| Aproxima el razonamiento humano | Sin aprendizaje automático |

**Ejemplo MYCIN:** reglas con factor de certeza para incertidumbre:

```
IF  organismo gram negativa AND morfología bacilo AND aerobio
THEN  probablemente Enterobacteriaceae (0.6)
```

## Arquitectura

```
 Interfaz de Usuario
        ↕
 Módulo de Justificación
        ↕
 Motor de Inferencia ↔ Base de Conocimientos ↔ Base de Hechos
```

| Componente | Qué hace |
|---|---|
| **Base de Conocimientos** | Saber experto (reglas, marcos, lógica, redes, ontologías) |
| **Base de Hechos** | Datos del problema actual |
| **Motor de Inferencia** | Combina BC + hechos → nuevas conclusiones |
| **Justificación** | Explica cómo se llegó a la conclusión |
| **Interfaz** | Interacción en lenguaje natural |

## Estrategias de Búsqueda

Explorar el estado de un problema: representación formal de todas las situaciones posibles, para encontrar la solución.

| Estrategia | Funciona | Uso |
|---|---|---|
| **Guiada por datos** | Hechos → solución | Encadenamiento adelante |
| **Guiada por objetivos** | Meta → hechos | Encadenamiento atrás |
| **Fuerza bruta** | Prueba todo | Problemas pequeños |
| **Profundidad** | Camino hasta el final | Objetivo "al fondo" |
| **Anchura** | Por niveles | Objetivo "a poca profundidad" |
| **Heurística** | Guía con info del dominio | Problemas grandes |

## Motor de Inferencia

El "cerebro" del sistema. Aplica reglas SI-ENTONCES sobre los hechos con dos estrategias:

### Encadenamiento Adelante

> *"¿Qué puede suceder después?"* — de datos a conclusiones (guiado por datos)

1. Tomar hechos disponibles
2. Buscar reglas cuya condición (SI) se cumpla
3. Ejecutarlas → nuevos hechos
4. Repetir hasta la meta

```
Hechos: {A,B} · R1: A y B→C · R2: C→E · R3: A y E→H → H
```

### Encadenamiento Atrás

> *"¿Por qué sucedió esto?"* — de la meta a los hechos (guiado por objetivos)

1. Partir del objetivo a demostrar
2. Buscar regla cuya conclusión coincida
3. La condición se vuelve subobjetivo
4. Repetir hasta encontrar hechos

```
Objetivo: H
R3: A y E→H → subobjetivo {A,E}
R2: C→E → subobjetivo {C}
R1: A y B→C → hecho {A,B} → H demostrado
```

| | Adelante | Atrás |
|---|---|---|
| **Técnica** | Basada en datos | Por objetivos |
| **Velocidad** | Lenta | Rápida |
| **Aplicaciones** | Monitoreo, control | Diagnóstico, clasificación |

## Intérprete de Reglas

Ejecuta las reglas en un bucle de 3 fases:

```
RECONOCER → RESOLVER → EJECUTAR → ¿nuevos hechos? (sí: repetir / no: parar)
```

1. **Reconocer:** reglas que se cumplen
2. **Resolver:** elegir UNA
3. **Ejecutar:** aplicarla y añadir hechos

| Componente | Función |
|---|---|
| **Memoria de trabajo** | Hechos actuales + generados |
| **Concatenador** | Compara condiciones con hechos |
| **Resolución de conflictos** | Decide qué regla ejecutar |
| **Actuador** | Aplica la regla, actualiza memoria |

> Separar intérprete de reglas = modificar la BC sin tocar el motor (modularidad).

## Estrategias de Control

Orden en que se aplican las reglas activas.

### Resolución de conflictos
| Método | Criterio |
|---|---|
| **Prioridad fija** | Peso del experto |
| **Recencia** | Hecho más reciente |
| **Especificidad** | Más condiciones gana |
| **Orden numérico** | Según definidas |

### Metarreglas
Reglas sobre reglas que orientan el razonamiento:

```
METARREGLA: priorizar diagnóstico sobre tratamiento
R1: SI fiebre y tos → resfriado
R2: SI resfriado → paracetamol
```

### Criterios de parada
- No hay **nuevos hechos**
- **Objetivo** demostrado
- **Límite** de iteraciones
