# Sistemas Expertos

Un **sistema experto** es un programa de IA que emula la capacidad de decisión de un experto humano en un dominio específico.

---

## Origen e Historia

### Nacimiento

Los sistemas expertos nacieron en la **década de 1960-1970**, dentro del campo de la **Inteligencia Artificial simbólica**, cuando los investigadores se dieron cuenta de que la IA general no era viable y había que enfocarse en **dominios específicos**.

- **1965 — DENDRAL:** el primer sistema experto, creado en Stanford por Buchanan y Feigenbaum para identificar estructuras químicas.
- **1970s — MYCIN:** desarrollado en Stanford por Shortliffe, diagnosticaba infecciones bacterianas y recomendaba antibióticos.
- **1980s — XCON/R1:** usado por DEC para configurar sistemas de computadoras; probó el valor comercial.

### Fragmentación

A partir de los años 80 y 90, el campo se fragmentó en múltiples enfoques, en lugar de un único "sistema experto estándar":

```
                Sistemas Expertos
                        │
        ┌───────────────┼────────────────┐
        │               │                │
   Sistemas        Razonamiento      Lógica
   basados en      basado en        difusa /
   reglas          casos (CBR)      incertidumbre
        │               │                │
   Redes          Aprendizaje       Sistemas
   semánticas /   automático /     híbridos
   marcos         redes neuronales
```

Las razones de esta fragmentación:

- Los **sistemas basados en reglas** eran difíciles de mantener y escalar.
- El auge del **aprendizaje automático** (años 90-2000) ofreció aprender de datos sin reglas manuales.
- El **razonamiento basado en casos** aportaba aprendizaje desde la experiencia.
- La **lógica difusa** solventó la incertidumbre que los sistemas binarios no manejaban.

## Tipos de Sistemas Expertos

Los sistemas expertos se clasifican según cómo representan y procesan el conocimiento:

| Tipo | Cómo funciona | Ejemplo |
|---|---|---|
| **Basados en reglas** | Usa reglas SI... ENTONCES... encadenadas para inferir conclusiones | MYCIN (diagnóstico de bacterias) |
| **Basados en marcos** | Representa el conocimiento en estructuras jerárquicas con atributos y valores, y herencia | Clasificación de objetos con propiedades |
| **Basados en lógica** | Aplica lógica de predicados y deducción formal | Sistemas Prolog |
| **Basados en redes semánticas** | Representa conceptos como nodos conectados por relaciones | Razonamiento sobre parentescos |
| **Basados en casos** (CBR) | Resuelve problemas nuevos recordando y adaptando soluciones a casos previos | Asistencia de soporte técnico |
| **Difusos** (*fuzzy*) | Trabajan con incertidumbre mediante lógica difusa, sin valores binarios | Control de climatización |

### Basados en reglas vs Basados en casos

| | Basados en reglas | Basados en casos |
|---|---|---|
| **Conocimiento** | Reglas extraídas del experto | Casos reales almacenados |
| **Razonamiento** | Deductivo (inferencia) | Recuerdo + adaptación |
| **Aprendizaje** | Requiere actualizar reglas | Aprende al añadir casos nuevos |
| **Explicación** | Fácil de justificar | Más difícil de explicar |

## Sistemas Expertos Basados en Reglas

Son el tipo más común y clásico de sistema experto. Representan el conocimiento como un conjunto de **reglas de producción** de la forma **SI... ENTONCES...**.

### Estructura de una regla

```
IF    <condición 1> AND <condición 2> ...   ← antecedente (premisas)
THEN  <acción o conclusión>                  ← consecuente

Ejemplo:
IF  fiebre AND tos AND estornudos
THEN  diagnóstico = resfriado común
```

### Componentes

| Componente | Contenido |
|---|---|
| **Memoria de trabajo** | Hechos actuales del problema |
| **Base de reglas** | Reglas SI-ENTONCES del dominio |
| **Motor de inferencia** | Aplica las reglas sobre los hechos |

### Características

- El conocimiento está **separado** de su uso (reglas ↔ motor de inferencia)
- Cada regla es una **unidad independiente** que captura una pequeña porción de conocimiento
- El conocimiento se puede **añadir o modificar** sin reescribir el sistema
- El razonamiento es **explicable**: se puede seguir el rastro de reglas disparadas

### Ventajas y desventajas

| Ventajas                                                   | Desventajas                                         |
| ---------------------------------------------------------- | --------------------------------------------------- |
| Modularidad: reglas independientes y fáciles de actualizar | Difíciles de mantener cuando hay cientos de reglas  |
| Explicabilidad: se justifica el razonamiento paso a paso   | Explosión combinacional en el conjunto de conflicto |
| Ampliables: se agregan reglas sin tocar el motor           | Conocimiento solo explícito (lo tácito se pierde)   |
| Aproximan el razonamiento humano                           | Sin capacidad de aprendizaje automático             |

### Ciclo de funcionamiento

```
1. Tomar hechos actuales (memoria de trabajo)
2. Explorar la base de reglas
3. Si ninguna regla aplica  →  detener
4. Si varias reglas aplican →  elegir una (resolución de conflictos)
5. Disparar la regla, añadir la conclusión como nuevo hecho
6. Volver al paso 1
```

### Ejemplo clásico: MYCIN

MYCIN, el sistema experto de los años 70, diagnosticaba infecciones bacterianas y recetaba antibióticos usando cientos de reglas IF-THEN. Las reglas incluían incluso un **factor de certeza** para manejar la incertidumbre:

```
IF    el organismo es gram negativa
AND   la morfología es bacilo
AND   el aerobismo es aerobio
THEN  es probablemente Enterobacteriaceae (0.6)
```

El 0.6 es un factor de certeza que indica cuánto confía la regla en su conclusión.

## Arquitectura

```
Interfaz de Usuario
        ↕
┌──────────────────────────────────-─┐
│       Módulo de Justificación      │
├───────────┬──────────-─┬───────────┤
│ Motor de  │  Base de   │  Base de  │
│ Inferencia│Conocimiento│  Hechos   │
└───────────┴──────────-─┴───────────┘
```

| Componente | Qué hace |
|---|---|
| **Base de Conocimientos** | Almacena el saber experto (reglas, marcos, lógica, redes semánticas, ontologías) |
| **Base de Hechos** | Guarda los datos concretos del problema actual |
| **Motor de Inferencia** | Combina BC + hechos para deducir nuevas conclusiones |
| **Módulo de Justificación** | Explica al usuario cómo se llegó a una conclusión |
| **Interfaz de Usuario** | Permite interactuar en lenguaje natural |

## Estrategias de Búsqueda

Los sistemas expertos resuelven problemas explorando un **espacio de estados** (todas las situaciones posibles). Para encontrar la solución se usan distintas estrategias de búsqueda:

### Clasificación

| Estrategia | Cómo funciona | Uso |
|---|---|---|
| **Guiada por datos** (forward) | Parte de los hechos y avanza hacia la solución | Encadenamiento hacia adelante |
| **Guiada por objetivos** (backward) | Parte de la meta y retrocede buscando hechos | Encadenamiento hacia atrás |
| **Fuerza bruta** (ciega) | Prueba todas las posibilidades sin información extra | Problemas pequeños |
| **Primero en profundidad** | Explora un camino hasta el final antes de retroceder | Cuando el objetivo está "al fondo" |
| **Primero en anchura** | Explora por niveles antes de profundizar | Cuando el objetivo está "a poca profundidad" |
| **Heurística** | Usa información del dominio para guiar la búsqueda | Problemas grandes, difícil definir meta al inicio |

> **Diferencia clave:** la búsqueda **guiada por datos** y la **guiada por objetivos** se corresponden directamente con los dos encadenamientos del motor de inferencia.

---

## Motor de Inferencia

Es el "cerebro" del sistema. Opera con reglas **SI... ENTONCES...** y tiene dos estrategias principales (basadas en la búsqueda guiada por datos y por objetivos):

### Encadenamiento Hacia Adelante

> **Pregunta:** *"¿Qué puede suceder después?"*
> **Parte de:** hechos conocidos → **llega a:** conclusiones
> **Tipo de búsqueda:** guiada por datos (forward)

**Pasos:**
1. Se toman los hechos disponibles
2. Se buscan reglas cuya condición (SI) se cumple
3. Se ejecutan → se obtienen nuevos hechos
4. Se repite hasta alcanzar el objetivo

```
Hechos: {A, B}
R1: SI A y B → C
R2: SI C → E
R3: SI A y E → H
→ Se infiere H
```

| Ventajas                             | Desventajas                           |
| ------------------------------------ | ------------------------------------- |
| Deduce mucho a partir de pocos datos | Genera info sin saber si es relevante |
| Ideal para planificación y monitoreo | Puede disparar reglas innecesarias    |

### Encadenamiento Hacia Atrás

> **Pregunta:** *"¿Por qué sucedió esto?"*
> **Parte de:** objetivo → **busca:** hechos que lo respaldan
> **Tipo de búsqueda:** guiada por objetivos (backward)

**Pasos:**
1. Se parte del objetivo a demostrar
2. Se busca una regla cuya conclusión (ENTONCES) coincida
3. La condición (SI) se convierte en subobjetivo
4. Se repite recursivamente hasta encontrar los hechos

```
Objetivo: H
R3: SI A y E → H  → subobjetivo: {A, E}
R2: SI C → E      → subobjetivo: {C}
R1: SI A y B → C  → hechos: {A, B}
→ H demostrado
```

| Ventajas                              | Desventajas                      |
| ------------------------------------- | -------------------------------- |
| Rápido, solo prueba reglas necesarias | El objetivo debe conocerse antes |
| Búsqueda dirigida y eficiente         | Difícil de implementar           |

### Cuándo usar cada uno

| | Hacia Adelante | Hacia Atrás |
|---|---|---|
| **Técnica** | Basada en datos | Impulsada por objetivos |
| **Velocidad** | Lenta | Rápida |
| **Aplicaciones** | Monitoreo, control | Diagnóstico, clasificación |
| **Ejemplo** | Predecir mercado | Diagnosticar enfermedad |

## Intérprete de Reglas

Es el componente que ejecuta las reglas en un bucle continuo de 3 fases:

### Ciclo RSE

```
RECONOCER → RESOLVER → EJECUTAR → ¿nuevos hechos?
   ↑                                    │
   └────────────────────────────────────┘
```

1. **Reconocer:** buscar todas las reglas que se cumplen
2. **Resolver:** elegir UNA (resolución de conflictos)
3. **Ejecutar:** aplicarla y añadir nuevos hechos

### Componentes del ciclo

| Componente | Función |
|---|---|
| **Memoria de trabajo** | Hechos actuales + intermedios generados |
| **Concatenador** (*matcher*) | Compara condiciones de reglas con hechos |
| **Resolución de conflictos** | Decide qué regla ejecutar |
| **Actuador** | Aplica la regla y actualiza la memoria |

> **Idea clave:** separar el intérprete de las reglas permite modificar la BC sin tocar el mecanismo de inferencia (modularidad).

## Estrategias de Control

Determinan **en qué orden** se aplican las reglas activas.

### Resolución de Conflictos

Cuando varias reglas se cumplen a la vez, hay que elegir una:

| Método | Criterio |
|---|---|
| **Prioridad fija** | Peso asignado por el experto |
| **Recencia** | Usa el hecho más reciente |
| **Especificidad** | La regla con más condiciones gana |
| **Orden numérico** | Según fueron definidas |

### Metarreglas

Son reglas de **mayor nivel** que controlan otras reglas:

```
METARREGLA: Priorizar diagnóstico sobre tratamiento
R1: SI fiebre y tos → resfriado
R2: SI resfriado → paracetamol
```

Orientan al motor para seguir un camino más eficiente.

### Criterios de Parada

El motor se detiene cuando:
- No se generan **nuevos hechos**
- El **objetivo** se demuestra verdadero/falso
- Se alcanza un **límite** de iteraciones
